## The algorithm

Independently reimplemented from the written description in doc 07 §"Algorithm
(CODE — verified)". **No WEBKNOSSOS source was read, copied, ported or
paraphrased**, per §E8's "prefer independent reimplementation of SDF method with
citation" and decision D3.

```
sdf(mask)  = edt(~mask) − edt(mask)          # outside +, inside −
blend(k)   = first_sdf·(1−k) + last_sdf·k
labelled   = blend < 0                        # strictly, per doc 07
```

`scipy.ndimage.distance_transform_edt` (BSD-3, already a declared dependency)
supplies the exact Euclidean transform, with `sampling=` carrying physical
spacing so anisotropy is handled by the metric rather than corrected afterwards.

Constants are named from the specification: `MAXIMUM_INTERPOLATION_DEPTH = 100`,
`MINIMUM_INTERPOLATION_DEPTH = 2`.

## Conflicts resolved

**A — "preview" is in the prompt but not in the saga.** Doc 07 records that
upstream *"applies stroke directly (CODE); DOC says review after"*. Resolved by
splitting the backend into `plan_interpolation()` (computes, writes nothing) and
`apply_interpolation()` (commits) — which is exactly what a preview needs, while
the frontend half stays out of scope.

**B — mito has no "active cell id" or viewport.** The caller passes `label_id`,
`axis`, `first_index`, `last_index` explicitly. Strictly more testable: no
hidden state, no dependence on interaction history.

**C — golden tests must not be generated by the code under test.** No fixtures
existed, and fabricating them from the new implementation would assert only that
the code agrees with itself. See below.

## Golden tests — provenance and the tolerance that emerged

`golden/make_golden_fixtures.py` derives expected outputs from **closed-form
geometry** and never imports the core (asserted by
`test_generator_does_not_import_the_core`). For concentric circles:

```
(1−k)(|p−c| − r₁) + k(|p−c| − r₂) = |p−c| − ((1−k)r₁ + k r₂)
```

so the interpolated shape is exactly the circle of interpolated radius.

**14 cases: 4 exact (analytic), 10 invariant-checked**, every array SHA-256
hashed in the manifest so an accidental regeneration shows in a diff.

> **The golden tests immediately earned their place.** The first run failed all
> 18 exact comparisons. Investigation showed the *expectation* was wrong, not
> the code: the closed form describes the **continuous** signed distance, while
> the specified algorithm uses a **discrete** Euclidean transform — distance to
> the nearest opposite-class voxel centre. They agree in the interior and differ
> only at the rasterised surface. Measured maximum deviation across every exact
> case: **0.44 voxels**.
>
> Resolved with an explicit, recorded tolerance: the analytic circle must be
> reproduced **exactly outside a 1-voxel band** around its boundary. That keeps
> the expectation independent while acknowledging discretisation honestly, and
> it still pins the interpolated radius to sub-voxel accuracy.

Cases with no closed form — topology split/merge, holes opening/closing,
translation, thin bars, diagonals, single voxels, boundary-touching objects —
are pinned by invariants that follow from the algorithm's definition, and the
manifest says so rather than dressing them as golden equality.

## A real limitation, asserted rather than hidden

Two tests failed on first run for a second, more interesting reason.

**SDF interpolation of widely separated objects produces empty intermediates.**
Two isolated voxels 4 apart have signed distance −1 only at themselves; at every
intermediate the blend is positive everywhere, so nothing is labelled. The same
happens for discs of radius 12 separated by 28.

This is inherent to the specified algorithm — doc 07 records upstream's own
warning that *"heuristics may err"* — not a defect here. It is now pinned by
`test_widely_separated_small_objects_yield_empty_intermediates` and
`test_translation_beyond_overlap_is_also_empty`, with
`test_translation_within_overlap_does_interpolate` as the complement, so the
boundary of the behaviour is documented and any future change to it is
deliberate.

It also invalidated the first anisotropy test, which compared two degenerate
empty results and would have passed as `0 == 0` while proving nothing. That test
now uses overlapping discs and additionally asserts the *direction* of the
effect.

## Measured behaviour

`bench_interpolation.py`. Pure core; no database involved.

### Bounded box versus naive dense — why §6 requires a bounding box

1024×1024 plane, one object, depth 8:

| Strategy | Plane processed | p50 | Peak memory | Voxels changed |
|---|---|---|---|---|
| naive dense | 1024 × 1024 | 423.44 ms | 59.4 MB | 18 915 |
| **bounded (bbox)** | 69 × 89 | **2.13 ms** | **0.35 MB** | 18 915 |

**199× faster, 168× less memory, identical output.** The benchmark asserts both
the speedup and the equality, so a regression to whole-plane processing fails
the benchmark rather than being published as a number.

### Scaling

| Plane | p50 | Peak |   | Depth | p50 | Peak |
|---|---|---|---|---|---|---|
| 64² | 1.42 ms | 0.2 MB | | 2 | 14.11 ms | 3.3 MB |
| 256² | 15.98 ms | 3.5 MB | | 10 | 15.67 ms | 3.8 MB |
| 512² | 81.07 ms | 13.8 MB | | 50 | 23.48 ms | 8.4 MB |

Cost scales with pixels, as expected. **Depth is nearly free** — the two signed
distance fields are computed once and only the blend repeats, so depth 50 costs
1.7× depth 2 rather than 25×.

Other labels present cost **nothing** (12.9–14.5 ms whether 1 or 64 other
segments exist), confirming that only the active label is transformed.
Anisotropy is free (14.3 vs 14.5 ms). Dense masks cost ~27 % more than sparse.

| Criterion | Target | Measured |
|---|---|---|
| Bounded beats dense | must | 199× |
| Bounded output identical to dense | must | identical |
| Depth scaling sub-linear | must | 1.7× for 25× depth |
| 256² depth 4 | < 100 ms | 16 ms |

## Phase 7 integration

**Exactly one operation per apply** — never one per slice or voxel. §E8's
"single undoable transaction" and Phase 7's bounded-payload rule agree here.

The payload records algorithm, version, axis, endpoints, depth, label, spacing,
overwrite mode, offsets, voxels changed, source version and bbox — **no voxel
data**, and measured well under 4 KB even at depth 50.

| Property | Behaviour |
|---|---|
| Atomicity | Plan first, then one transaction: operation row, then writes. A write failure rolls the operation back — asserted by `test_write_failure_rolls_back_the_operation`. |
| Idempotency | Replay returns the original **and does not re-apply**. |
| Same key, different parameters | **Rejected** (`idempotency_conflict`) — Phase 7 returns the original on key match, so Phase 8 compares parameters rather than handing back a result that does not match the request. |
| Version conflict | Raised with rebase data; nothing written. |
| Locked task | Refused, consistent with Phases 5 and 7. |
| Concurrency | 4 concurrent applies → dense sequence 1–4; 4 concurrent replays of one key → exactly one operation. |

`write_slice` is injected by the caller, so the service never learns the storage
format — which is what lets it be tested without a volume on disk.

## Known limits

- **Undo does not restore voxels.** Phase 7 deferred the snapshot store, so
  undo marks the operation reversed without repainting. Asserted by
  `test_undo_does_not_restore_voxels` so the limit is visible.
- **Widely separated objects interpolate to nothing** — see above. Inherent.
- **No chunked/streaming processing.** Bounded by `MITO_INTERPOLATION_MAX_VOXELS`
  (64 M) instead; larger regions must be split by the caller.
- **No HTTP endpoint and no management command**, per ADR-006 §9 and the Phase 7
  precedent — §E8 describes UX, not an API.
- **No preview UI**, only the backend split that enables one.
- 2-D endpoint planes only; the interpolation axis is the caller's third
  dimension.

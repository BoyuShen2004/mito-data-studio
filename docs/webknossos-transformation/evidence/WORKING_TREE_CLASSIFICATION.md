## 1. Method

Provenance was established by **diffing against the pre-work snapshot**, not by
reading timestamps. Timestamps corroborate but never decide — a file touched by
a formatter would lie.

For each of the 61 tracked files dirty at baseline, the baseline per-file patch
was reapplied to its `HEAD` blob to reconstruct the exact pre-work working copy,
then compared byte-for-byte with the current file. That distinguishes *"the user
changed this and I never touched it"* from *"we both changed it"* with certainty.

|---|---|

## 6. Blocker — Phase 0.5 / 1 / 2 / 3 cannot be committed independently

Five commits are blocked, all for the same reason: **the transformation work was
built on top of uncommitted user WIP, and depends on it.** This was not visible
until staging was attempted.

### 6.1 The migration graph

| My migration | depends on | status of that dependency |
|---|---|---|
| `accounts/0004_team_…` | `accounts/0003_userprofile_contact_note_…` | **untracked user WIP** |
| `annotation/0007_annotationtask_pending_instances_…` | `annotation/0006_submit_lock_and_project_hard_cases` | **untracked user WIP** |

Committing Phase 1 or Phase 2 without those two files produces a repository
whose migration graph does not resolve — a fresh clone raises
`NodeNotFoundError` and cannot migrate at all. Phase 3 (`annotation/0009`)
inherits the same problem transitively.

### 6.2 Phase 0.5 rewrites user WIP rather than sitting beside it

`_normalize_label_type` **does not exist at `HEAD`.** It was introduced by the
user's uncommitted work, and the Phase 0.5 fix is a rewrite of it. Verified:

```
$ git show HEAD:backend/volumes/services.py | grep -c _normalize_label_type
0
```

So there is no "my hunks only" version of `backend/volumes/services.py` that
compiles: the function being corrected belongs to the user's WIP. 40 further
lines of their WIP remain in that file around it.

### 6.3 Resolution — the owner's call

| Option | Consequence |
|---|---|
| **A. Owner commits their WIP first** (recommended) | The natural order. The five blocked commits then stack on top unchanged, with correct authorship on both sides. |
| **B. Authorise a single clearly-attributed commit of the user's WIP** | Same result, but their feature lands in one lump authored through this session rather than as they would have split it. |
| **C. Re-parent the migrations onto the last tracked node** | Avoids committing their work, but creates a migration *branch* the moment they commit theirs, requiring a merge migration. It also silently rewrites dependency assumptions in files they own. **Not done unilaterally.** |

Option C is technically available and was deliberately **not** taken: it trades
a visible blocker for a hidden one in someone else's files.

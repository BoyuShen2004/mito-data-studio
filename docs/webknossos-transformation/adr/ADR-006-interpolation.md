### The algorithm, exactly

From doc 07 §"Algorithm (CODE — verified)":

1. Binary masks for the **active cell id** on the first and last slices.
2. Signed distance transform of each: **outside positive, inside negative**,
   built by transforming the mask and its inverse and combining by `absMax`.
3. For each intermediate slice at `k = offset / depth`:
   `weighted = first_sdf * (1 − k) + last_sdf * k`; label where `weighted < 0`.
4. `MAXIMUM_INTERPOLATION_DEPTH = 100`, depth ≥ 2.
5. Anisotropic spacing respected.
6. Overwrite policy respected.
7. One undoable transaction.

## 2. Conflicts found, and how they were resolved

### Conflict A — "preview" is required by the prompt but absent from the saga

§E8 wants "annotate A → annotate B → Interpolate → **preview** → confirm/cancel".
Doc 07 records that the real saga *"applies stroke directly (CODE); DOC says
review after"* — i.e. upstream has no preview step, and its own documentation
merely advises checking afterwards.

**Resolution.** Preview is a **UI** concern, and Phase 8's gate is golden tests,
not UX. The core is therefore built as a **pure function returning the proposed
labels without writing anything**, and a separate apply step commits them. That
is precisely what a preview needs — compute, show, then confirm — so the backend
half of the requested UX exists while the frontend half stays out of scope.
`plan_interpolation()` is the preview; `apply_interpolation()` is the confirm.

### Conflict B — mito has no "active cell id" or viewport

The saga derives the plane and the active segment from the last label action in
a live viewport. mito's backend has neither: it stores labelled slices in a
memmap TIFF and has no notion of a cursor.

**Resolution.** The caller passes them explicitly: `label_id`, `axis`,
`first_index`, `last_index`. This is a **strictly more testable** interface —
no hidden state, no dependence on interaction history — and it is what makes the
core a pure function. The "active label only" semantics of §E8 are preserved:
exactly one label is interpolated per call.

### Conflict C — golden tests must not be generated by the code under test

The gate is golden tests, but none exist in the repository, and Step 4 of the
brief forbids fabricating expected outputs from the new implementation.

**Resolution — analytic expectations.** For concentric circles the SDF blend has
a closed form. With `d_i(p) = |p − c| − r_i`, the blend at fraction `k` is

```
(1−k)(|p−c| − r₁) + k(|p−c| − r₂) = |p−c| − ((1−k)r₁ + k r₂)
```

so the interpolated shape is **exactly** the circle whose radius is the linear
interpolation of the endpoint radii. That expectation is derived from geometry,
never from the implementation, and it pins the algorithm's defining property.

Fixtures are generated by `tools/make_golden_fixtures.py`, which computes
expected masks from **closed-form geometry only** and never imports the
interpolation core. Cases without a closed form (topology change, holes) are
pinned by **invariants** that follow from the algorithm's definition rather than
by exact arrays — stated as such in the manifest rather than dressed up as
golden equality.

Every fixture and expectation is SHA-256 hashed in the manifest, so an
accidental regeneration is visible in a diff.

## 3. Mathematical decisions

| Question | Decision |
|---|---|
| Method | Signed distance transform + linear blend, per doc 07. |
| Distance units | **Physical**, via `scipy.ndimage.distance_transform_edt(sampling=…)`. Anisotropy is a first-class input, not a correction. |
| SDF convention | Outside **positive**, inside **negative**; boundary voxels of the object have distance 0 and are treated as inside (`< 0` after the half-voxel convention below). |
| Half-voxel convention | `sdf = edt(~mask) − edt(mask)`. A voxel just inside the object gets −1, just outside +1. This reproduces `absMax` of the two transforms with the sign convention above. |
| Ties (`weighted == 0`) | **Not labelled.** The rule is `< 0`, taken literally from doc 07. A tie is the surface itself, and including it would thicken every interpolated object by one voxel. |
| Holes | Handled implicitly — a hole is positive-distance interior, so it survives the blend. No special casing. |
| Disconnected components | Implicit. Two blobs blend independently because the SDF is local to the nearest surface. |
| Topology change | Permitted and expected. A split or merge between endpoints produces a plausible intermediate; doc 07 explicitly says topology can change. |
| One endpoint empty | An empty mask has **no** zero level set, so its SDF is undefined. Rather than invent `+inf`, this is **rejected** with a clear error: interpolating from nothing is not interpolation, it is extrapolation. |
| Endpoints identical | Every intermediate equals the endpoints. Asserted. |
| Multiple keyframes | **Pairwise only.** Chained interpolation is the caller's job, matching the saga, which advances its "last label" reference and interpolates the next pair. |

## 4. Label semantics

- **One label per call.** `label_id` selects the segment; every other label is
  untouched. This is §E8's "active segment only".
- **Label 0 is background and is reserved** — it cannot be interpolated
  (`label_id != 0` enforced), because "interpolate the background" has no
  meaning.
- **Negative labels rejected**; the working label dtype is unsigned.
- **dtype is preserved**: the output carries the input's dtype, and `label_id`
  must be representable in it.
- Overlap between the interpolated label and existing labels is governed by the
  **overwrite mode**, not by silent precedence.

### Overwrite modes

| Mode | Behaviour |
|---|---|
| `overwrite_all` | Interpolated voxels replace whatever is there. |
| `overwrite_empty` | Interpolated voxels are written only where the target is currently background. Existing segments win. |

Matching the saga's `overwriteMode`. Default is `overwrite_empty` — the
conservative choice, because silently destroying an existing segment is the
worse failure.

## 5. Determinism

Every source of nondeterminism is closed deliberately:

| Risk | Mitigation |
|---|---|
| Iteration / hash order | The core takes arrays and returns arrays. No dict iteration affects output. |
| Connected-component ordering | Not used. The SDF is computed globally per mask, never per component. |
| Floating-point ties | Comparison is a single `< 0` on float64. No epsilon, no tolerance, so the result is a pure function of the inputs. |
| Library version | `distance_transform_edt` is exact Euclidean, not an approximation, so its output is version-stable for a given input. Pinned `scipy>=1.11`, recorded in the manifest. |
| CPU/GPU | CPU only. No GPU path exists. |
| Database row order | The core never touches the database. |
| Parallelism | The core is single-threaded and stateless; concurrent calls cannot interfere. |

`test_determinism_across_repeated_runs` and a fresh-process check pin this.

## 6. Storage and memory

- Operates on a **dense bounding-box sub-array**, never the whole volume. The
  caller supplies the box; the core never loads image data itself.
- **Maximum accepted size** is bounded by `MITO_INTERPOLATION_MAX_VOXELS`
  (default 64 M voxels, ≈ 64 MB at uint8, ≈ 512 MB at float64 intermediate).
  Over that, the call is rejected before any allocation rather than after an
  OOM.
- Peak memory is ~4 float64 planes plus the output block; measured in the
  benchmark.
- **No temporary files.** No cleanup path is needed because nothing is written
  until the apply step, which is a single transaction.
- Chunked/streaming interpolation is **not** implemented — see §11.

## 7. Phase 7 integration

Interpolation records **exactly one** `AnnotationOperation` per successful
apply, never one per voxel, slice or chunk. §E8 requires "single undoable
transaction" and Phase 7 requires bounded payloads; one operation satisfies
both.

The payload records what is needed to understand and reproduce the call:
actor, axis, first/last index, label id, algorithm name and version,
spacing, overwrite mode, affected bounding box, voxels changed, source version,
and the resulting version. **No dense voxel array** — that would violate
ADR-005 §2 and the size cap.

| Requirement | Behaviour |
|---|---|
| Atomicity | Compute first, then one transaction: append the operation and write the labels. A failure before commit leaves nothing. |
| Idempotency | Phase 7's `idempotency_key`. A replay returns the original operation and does **not** re-apply. |
| Same key, different parameters | **Rejected** — Phase 7 returns the original on key match, so Phase 8 compares parameters and raises rather than silently returning a result that does not match what was asked. |
| Expected version | Passed through to Phase 7; a stale version raises `VersionConflict` carrying the missed operations. |
| Locked annotation | Refused, consistent with Phase 5 and Phase 7 undo. |
| Undo | Phase 7's append-only undo. **Caveat in §11.** |
| Sequence | Increments exactly once per apply. |

## 8. Concurrency

Lock target and ordering are Phase 7's, unchanged: the task row, taken during
sequence allocation. Interpolation adds no new lock class.

Concurrent modification of the source slices between plan and apply is detected
by `expected_version`, which is why the two-step API exists at all: a preview
computed against version 7 cannot be applied blindly at version 9.

## 9. API boundary

**No HTTP endpoint in this phase.** §E8 describes UX, not an API, and Phase 7
established the precedent that a phase may deliver model and service only. The
services are importable and a management command is *not* added either, because
neither is required by the written scope and every entry point is surface that
must then be secured, rate-limited and bounded.

Compute time is bounded by the voxel cap; when a real endpoint is added it
should validate the box, run the plan, and return an identifier — the split
already exists for exactly that reason.

### 9a. Amendment — the endpoint and the toolbar UI (added later)

The frontend half is now built, so §1's "Excluded" row and §11's "No preview
UI" no longer describe the system. Nothing in §§1–8 changed: the core and the
two services are used exactly as designed, which is what made this a small
addition rather than a rewrite.

`POST /api/tasks/<id>/interpolate/` with `mode: "preview" | "apply"`, wired to
`annotation.services.plan_task_interpolation` /
`apply_task_interpolation`. Decisions worth recording:

- **Preview returns masks; apply does not accept them.** An apply re-plans
  server-side from the same `(axis, first_index, last_index, label)`. Accepting
  the previewed voxels back would let any caller write geometry the algorithm
  never produced, and would make the recorded operation payload a description
  of something other than what was written. The cost is one extra plan; the
  benefit is that the endpoint has no "trust the client's pixels" path at all.
- **Masks travel as label-RLE**, the same wire shape `predict-mask/` already
  uses for AI proposals — a boolean mask is a label slice with two values, and
  reusing it means the canvas has one decoder, not two.
- **Registered unconditionally, gated in the view (503).** Routing that appears
  and disappears with a flag makes "is it enabled?" indistinguishable from "is
  it deployed?" — the same rule the chunk-service routes follow.
- **Editors only, for preview as well as apply.** Preview reads the *working*
  copy, which is staged, unapproved work; planning against it is not a public
  read.
- **The UI needs both flags.** `FEATURE_INTERPOLATION` alone would give a
  preview that can never be confirmed, so the tool button is shown only when
  the deployment identity reports `FEATURE_INTERPOLATION` **and**
  `FEATURE_ANNOTATION_OPS`. Hidden, not disabled: a button that always 503s is
  indistinguishable from a broken one.

§11's undo limit is unchanged and is now the reason the UI is shaped the way it
is — see below.

## 10. Rollout

`FEATURE_INTERPOLATION`, default **False**. With it off, both services refuse
with `reason="disabled"` and nothing else changes.

**No migrations.** Phase 8 stores nothing new: interpolation writes labels
through the existing working-label path and records one Phase 7 operation in an
existing table.

Rollback is the flag. Operations recorded while it was on remain valid Phase 7
rows.

## 11. Known limits, accepted deliberately

- **Undo does not restore voxels.** Phase 7's undo appends an inverse *record*;
  it does not revert the working label, because Phase 7 explicitly deferred the
  snapshot/chunk store that would make that possible. Undoing an interpolation
  marks it undone in the log; the labels stay. This is stated in the phase doc
  and asserted by test rather than left for someone to discover.
  Consequence for the toolbar UI (§9a): **Confirm is the point of no return.**
  The canvas's Undo button is a per-slice in-memory history of the slice on
  screen; an interpolation writes many slices on the server, so Undo cannot
  reach them and must not be advertised as if it could. That is why the UI
  spends its safety budget *before* the write — plan, render on every
  intermediate slice, Cancel costs nothing — instead of promising a way back
  afterwards. The wording in the tool row says applied, not undoable.
- **No chunked processing.** Bounded by the voxel cap instead. A volume larger
  than the cap must be interpolated in caller-chosen boxes.
- **`float64` intermediates** cost 8× the mask size; the cap accounts for it.

## 12. Acceptance criteria

1. Concentric-circle golden cases match the analytic expectation **exactly**.
2. Endpoints are reproduced exactly at `k = 0` and `k = 1`.
3. Identical endpoints produce identical intermediates.
4. Anisotropic spacing changes the result in the direction geometry predicts.
5. Repeated runs and a fresh process produce byte-identical output.
6. One apply → exactly one operation, bounded payload, no dense voxels.
7. Flag off → nothing runs, nothing changes.

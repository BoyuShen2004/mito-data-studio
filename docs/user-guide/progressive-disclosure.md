# Expand grouped lists when needed

Disclosure is used to separate multiple groups or records with detailed contents,
not to hide every information block. Select a heading with an arrow to expand
or collapse it. Tab focuses the button; Enter or Space activates it. Expanding
never saves data, changes permissions or applies an operation.

## People and teams

**Your profile** and its Edit button are directly visible. People rosters with
multiple people show a section summary first, then individual expandable records.
A roster containing only one person displays that person's details directly.
Empty ordinary rosters display their empty-state message without an extra click.
The **Assistant managers** group has its own collapse control even for a single
person. It shows no Time report; the Annotators roster retains manager Time
controls. Person headings display the role once, including both roles for dual
accounts. Grant/revoke controls sit after the other record contents.

Managers open **Teams & assignment eligibility** to manage existing teams.
Within a multi-team list, expand a team for members, description/organization
when available, editing and project controls. A lone team displays its details
directly inside the group. **New team** is a normal form without its own
collapse control. If there are no teams, creation is directly visible.

Membership controls still apply immediately. **Rename** explicitly saves a name;
**Delete team** retains confirmation and assignment-impact warnings. Person name
links open their dedicated pages; annotation time keeps its existing drill-down.

## Datasets and directly visible sections

Project **Data** folds individual datasets when there is more than one dataset.
Each heading retains its name and volume count; expansion reveals metadata,
volumes and management controls. A single dataset displays those details directly.
Dataset editors retain independent pending drafts.

Single-purpose sections remain directly visible: project Annotator workload,
project access members, personal project lists, workload/projects on a dedicated
person page, and optional registration metadata. They do not need another click
merely because they contain a table or form. Primary work lists, editor tools,
scientific context, review decisions and warnings keep their existing presentation.

## Drafts and refreshes

Collapsing a grouped list retains pending input while staying on the page. It is
not a save: use explicit Save, Rename, Create or Register controls. Closing an
edit form or leaving the page can discard its draft. Save intentional changes
before navigating. Expansion state is not stored across page reloads.

When a visible singleton collection grows, its contents remain visible and its
form stays mounted. When a collection shrinks to one record, details become
directly visible. Existing annotation-time and submission-history disclosures
keep their own behavior.

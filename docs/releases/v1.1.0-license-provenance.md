# v1.1.0 licence and provenance gate

Audit date: 2026-08-01. This is an engineering provenance record, not legal
advice.

## First-party and WEBKNOSSOS relationship

The root `LICENSE` is an explicit no-licence-granted notice because no
authorised open-source grant was supplied. Repository history, path comparison,
and the attribution register found no copied or adapted WEBKNOSSOS application,
datastore, tracingstore, or Python-package source. WEBKNOSSOS remains a
behavioural/architectural reference. Consequently no AGPL-derived source is in
the served application. If this fact changes, the AGPL review gate in
`THIRD_PARTY_NOTICES.md` applies before commit or deployment.

## Locked dependency inventory

The release audit runs `ops/release/audit_dependency_licenses.py` with the
release Python 3.11 venv and the result of `npm ci`. It enumerates the packages
actually installed from `requirements-release.txt` and
`frontend/package-lock.json`, not an unpinned global environment.

Result:

- Python distributions: 57 (including the venv bootstrap tooling); missing
  licence evidence: 0.
- JavaScript packages: 181 after the React Router 7.18.2 update; missing
  licence evidence: 0.
- AGPL dependencies: 0. The `webknossos` Python package is absent.
- Notable non-MIT/BSD/Apache terms: psycopg LGPL-3.0-only; tqdm MPL-2.0 and MIT;
  caniuse-lite CC-BY-4.0; NVIDIA CUDA runtime wheels under NVIDIA proprietary
  terms; SciPy binary notices include the GCC Runtime Library Exception and
  libquadmath LGPL terms.

Release obligation: retain package `.dist-info`/licence files and npm package
licence texts when redistributing the runtime or a frontend dependency bundle;
retain the two vendored Apache-2.0 files and attribution register. A public
network deployment alone does not turn independently implemented code into
WEBKNOSSOS-derived code; this record does not decide obligations for a future
distribution or future copied code.

## Security-advisory disposition

React Router was upgraded from 6.30.4 and is exactly pinned to 7.18.2 to remove
the open-redirect/XSS advisories affecting the old line. On 2026-08-01,
`npm audit --omit=dev` reports two high package entries for the same reviewed
advisory, [GHSA-qwww-vcr4-c8h2](https://github.com/advisories/GHSA-qwww-vcr4-c8h2).
The upstream advisory says it affects only unstable React Server Components
APIs and lists 8.3.0 as patched, but 8.3.0 is not present in the npm registry
used by this release. This application is a client-only Vite SPA: it imports no
RSC server router, defines no React Router actions/loaders, and has no RSC
hydration endpoint. Therefore the vulnerable execution path is absent. The
advisory remains visible and is not represented as fixed. Track and validate
8.3.0 (or a later non-overlapping release) when it becomes available from the
approved registry.

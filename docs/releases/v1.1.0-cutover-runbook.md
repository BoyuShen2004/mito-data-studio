# v1.1.0 cutover and rollback runbook

This runbook supersedes the historical 18188 procedure for this release. The
commands are scoped to the current versioned paths and must be accompanied by
the release evidence record.

| Role | Path/service | Port |
|---|---|---:|
| retained rollback | `/home/weidf/shenb/mito-data-agent-production-v1.0.0`; `mito-data-agent-v1.0.0.service` | 18190 |

The generic `cloudflared.service` and every non-mito hostname in the shared
configuration are out of scope and must remain unchanged.

## Freeze and synchronization invariants

1. Back up the current tunnel file, systemd unit, protected v1.0 environment,
   database, data root, and source/reference inventory into a new root-owned
   timestamped directory outside all repositories.
2. Verify the custom PostgreSQL archive with `pg_restore -l`, verify every
   archive/data manifest and reject a zero-byte result.
3. Install the freeze Nginx listener privately, validate it with `nginx -t`,
   then change only the mito tunnel target from 18190 to 18193.
4. Confirm public GET succeeds and an authenticated mutation receives 503.
   Wait for PostgreSQL activity and access logs to show no in-flight mutation
   before recording the freeze start.
5. Take the final frozen database archive and synchronize the old data root to
   the new versioned root. Restore into a new database; never migrate the old
   database in place and never point v1.1 at the v1.0 mutable root.
6. Run migrations/reconciliation, row-count and hash comparisons, and only then
   start the private v1.1 service.

Restore the archive as the target service role. `--no-owner` alone is not
sufficient when the archive is restored by the cluster administrator: without
`--role`, restored tables and sequences belong to that administrator and the
application cannot even read `django_migrations`.

```bash
sudo cat FINAL_BACKUP/production.pgdump | \
  docker exec -i mito-dev-postgres pg_restore \
    -U mito --role=mito_production_v11 \
    -d mito_production_v1_1_0 --no-owner --no-privileges

docker exec mito-dev-postgres psql -U mito -d mito_production_v1_1_0 -Atqc \
  "select count(*) from pg_class c join pg_namespace n on n.oid=c.relnamespace
   where n.nspname='public' and c.relkind in ('r','S')
     and pg_get_userbyid(c.relowner)<>'mito_production_v11'"
```

The owner query must print exactly `0` before running migrations. Do not repair
this gate with ad-hoc grants: drop and recreate only the new v1.1 database,
then repeat the role-scoped restore. Never run these commands against the
v1.0 database.

For a local detached clone, use `GIT_LFS_SKIP_SMUDGE=1`, import the three exact
OID-addressed objects from the already verified local LFS store into the new
checkout's own `.git/lfs/objects`, then run `git lfs checkout`, `git lfs fsck`,
and `sha256sum`. A pointer file, shared mutable LFS storage, or an unverified
copy is a release blocker. Normal remote clones should fetch the same OIDs from
the configured LFS endpoint.

## Cutover

After the private identity and workflow gates pass, change only:

```yaml
  - hostname: mito-data-agent.seg.bio
    service: http://127.0.0.1:18191
```

Validate the YAML/configuration and restart only
`cloudflared-demo-seg-bio.service`. Keep v1.0.0 running on 18190. Verify public
HTTPS, cookie/CSRF behavior, deployment identity, authenticated workflows and
the synthetic Save/reload write target before ending the freeze.

When an `EnvironmentFile` value changes, use a full `systemctl restart` and
wait for `/readyz`; gunicorn HUP/`systemctl reload` replaces workers but retains
the environment inherited by the existing master. Use reload only for the
worker-restart resilience gate when configuration is unchanged.

## Exact ingress rollback

The final backup directory contains `config/demo-seg-bio-local.yml`, captured
immediately before freeze. On any rollback trigger:

```bash
sudo install -o root -g root -m 0600 \
  FINAL_BACKUP/config/demo-seg-bio-local.yml \
  /etc/cloudflared/demo-seg-bio-local.yml
sudo systemctl restart cloudflared-demo-seg-bio.service
curl -fsS https://mito-data-agent.seg.bio/login >/dev/null
```

Then prove that 18190 is still owned by `mito-data-agent-v1.0.0.service`, the
public URL reaches that PID/checkout, and its known Save/reload path works.
Retain the failed v1.1 DB/data/logs for forensics. Do not copy new masks back
ad hoc; preserving post-cutover edits requires a separate, explicit and
verified reconciliation while writes remain frozen.

## Rollback triggers

Rollback immediately for a wrong data-root write, lost edit, corrupt mask,
source/reference mutation, auth/CSRF failure, migration/integrity failure,
sustained 500s, identity mismatch, public workflow regression, or unsafe
AI/processing behavior. Neither checkout is deleted during observation.

## Deployed checkout working-tree audit

The v1.0.0 production checkout is not a clean representation of its reported
commit: it contains local tracked and untracked application files. Every such
file was compared with the integrated release. Fourteen are byte-identical to
release files. The remaining eight are strict release supersets covering the
profile/health checks, automatic legacy-pair compatibility, dashboard, and
router behavior. No application behavior exists only in the old checkout.

The release does not copy that dirty checkout. It is built from a clean clone
and exact commit, while the dirty checkout is retained unchanged as rollback
evidence. This makes the development/release history the authoritative source
without destroying the operator's current rollback state.

## Scope examined

The diff audit covered backend models/migrations/APIs, frontend flags/routes and
production build, startup/systemd/nginx/cloudflared contracts, health/readiness/
metrics/request IDs, processing/Slurm command boundaries, AI model paths,
licence/provenance documents, and deployment identity. Capability-level results
are recorded in `v1.1.0-traceability.md`; runtime validation is recorded in
`v1.1.0-validation.md`.

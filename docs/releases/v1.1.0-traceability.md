## Explicit production feature contract

`MITO_UPGRADE_PROFILE=production_integrated_v1` is validated at startup.
Individual `FEATURE_*` drift is rejected except for the documented coherent
four-switch pyramid/chunk emergency rollback.

| Feature | State | Reason / dependency | Rollback impact |
|---|---|---|---|
| teams | enabled | access model and audit foundation | full v1.0 service rollback |
| auto-fill scheduler | enabled | writes canonical single assignee directly | disable scheduler flag |
| review history | enabled | immutable review trail | full v1.0 service rollback |
| dashboards | enabled | read-only aggregates | profile rollback not needed |
| annotation ops | enabled | durability/history foundation | full v1.0 service rollback |
| interpolation/tools | enabled | operation log required | full v1.0 service rollback |
| autosave/recovery | enabled | operation log required | full v1.0 service rollback |
| volume pyramids | enabled | registration queues an additive validated derivative | turn all four streaming switches off; source remains authoritative |
| chunk service | enabled | pyramid dependency required | coherent four-switch rollback |
| PullQueue | enabled | chunk service required | rebuild SPA with both Vite switches off |
| chunk renderer | enabled for ready volumes | PullQueue required | source-slice fallback remains available |
| real local commands | disabled | executable allow-list empty | none |
| Slurm / nnU-Net | disabled | no approved production command/model/cluster job | none |

The same startup check also pins the provider/runtime contract: basic QC,
in-app proofreading and visualization, placeholder publishing, real SAM2
tracking, CPU EfficientSAM, local processing substrate, empty executable and
processing-environment allow-lists, PostgreSQL, bearer-protected metrics, and
the exact byte sizes of all three offline model assets. Drift is a deployment
error, not an informal operator convention.

The locked production build omits demo credentials and the development reset
UI. A deliberately disposable demo deployment may expose the passwordless
reset only when both `ENABLE_MOCK_DEV_LOGIN=1` and
`MITO_ALLOW_DEV_RESET=1` are explicitly configured; an orphaned reset switch
on a public host remains a deployment error.

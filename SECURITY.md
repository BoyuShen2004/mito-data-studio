# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability or include secrets,
patient data, private volume paths, tokens, or exploit details in logs. Use the
repository's private GitHub security-advisory channel, or contact the repository
maintainers privately when that channel is unavailable.

Include the affected version, deployment profile, impact, reproduction steps,
and any safe mitigation. Maintainers will acknowledge the report, assess scope,
and coordinate a fix and disclosure timeline.

Only the current development branch and the active production release receive
security fixes. Deployment secrets, TLS termination, host permissions, backups,
and access to registered source data remain operator responsibilities.
